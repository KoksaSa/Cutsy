## 🔐 2. Система лицензирования (Account-Based)

### Архитектура:
| Компонент | Описание |
|-----------|----------|
| **Backend** | Google Apps Script v3.0 (Web App) |
| **База данных** | Google Sheets (листы: users, licenses, config, logs) |

### Листы Google Sheets:

**users:**
| Столбец | Поле | Описание |
|---------|------|----------|
| A | email | Уникальный email пользователя |
| B | password_hash | SHA-256 хеш пароля |
| C | license_key | Активированный ключ |
| D | activated_at | Дата активации |

| G | device_tokens | Привязанные устройства (через \|\|) |

| I | max_devices | Макс. устройств (1 для 1 месяц/6 месяцев, 2 для 1 год) |

| Столбец | Поле | Описание |
|---------|------|----------|
| A | key | Лицензионный ключ (CUTSY2-PRO-...) |

| Параметр | Значение |
|----------|----------|

### Формат ключа:
```
CUTSY2-PRO-XXXX-XXXX-XXXXXXXX-XXXXXXXX
```

### Принцип работы:

1. **Регистрация пользователя:**
   - Пользователь вводит email и пароль
   - Backend проверяет уникальность email
   - Пароль хешируется (SHA-256)
   - **Автоматически выдаётся первый свободный ключ из licenses**
   - Ключ записывается в users для этого email
   - EmailJS отправляет приветственное письмо
   - **Telegram бот отправляет админу уведомление с ключом**

2. **Вход в систему:**
   - Проверка email + password_hash
   - Проверка лимита устройств (по умолчанию 1)
   - Генерация sessionToken
   - Сохранение в localStorage

3. **Активация ключа:**
   - Пользователь вводит ключ вручную (если нужен другой)
   - Backend проверяет, не использован ли ключ
   - Если ключ свободен — привязывает к email
   - Устанавливает expires_at = +60 дней

4. **Проверка лицензии:**
   - При запуске проверяется срок в localStorage
   - Серверная проверка каждые 2 дня
   - Если срок истёк — требуется повторная активация

2. Создай листы: `users`, `licenses`, `config`, `logs`
3. Открой **Расширения → Apps Script**

5. **Развернуть → Управление развёртываниями → Развернуть как Web App**
6. Доступ: **Все** (Anyone)
7. Скопируй URL в `js/license.js` → `GOOGLE_SCRIPT_URL`
8. **ВАЖНО:** После любого изменения backend пересобери frontend: `npm run build`

### 🔐 Безопасность (v3.0):

| Мера | Описание |
|------|----------|

| **Rate limiting** | 10 запросов в минуту на IP/email |
| **Кэширование** | Sheets, Config (6 часов) |
| **Secrets** | PropertiesService (TG_BOT_TOKEN, TG_CHAT_ID) |

1. **Сохрани** код (Ctrl+S)
2. **Переразверни** (Управление развёртываниями → Изменить → Развернуть)

## ⚙️ 5. Ключевые изменения в сессии

### 5.1 Zoom относительно курсора
**Проблема:** Холст зумировался относительно центра координат.

**Исправление:** Вычислять панорамирующий сдвиг при зуме:
```javascript
// js/mouse-events.js
const mouseX = e.clientX - rect.left - canvas.width / 2;
const mouseY = e.clientY - rect.top - canvas.height / 2;
const worldX = mouseX / oldZoom - panX / oldZoom;
const worldY = mouseY / oldZoom - panY / oldZoom;
panX = mouseX - worldX * newZoom;
panY = mouseY - worldY * newZoom;
```

**Результат:** Зум как в Google Maps — точка под курсором остаётся на месте.

### 5.2 DXF Bulge Arc
**Проблема:** Сложная логика с `isNearHalfCircle` для дуг.

**Исправление:** Использовать стандартную DXF формулу:
```javascript
// dxf-import.js
const sweepAngle = 4 * Math.atan(Math.abs(bulge));
const radius = chordLength / (2 * Math.sin(sweepAngle / 2));
const direction = bulge > 0 ? 1 : -1;
```

**Результат:** Упрощённая и понятная логика, соответствующая DXF спецификации.

### 5.3 Исправление "Наложение деталей" после раскладки
**Проблема:** После мульти-листовой раскладки кнопка «Наложение деталей» всегда сбрасывалась в OFF, даже если до раскладки была включена.

**Исправление:** Сохранять состояние `allowOverlap` перед раскладкой и инвертировать его после завершения:
```javascript
// index.html
const allowOverlapBeforeNesting = allowOverlap;
// ... после раскладки ...
allowOverlap = !allowOverlapBeforeNesting;
```

### 5.4 Зелёные точки привязки для инструмента Line
**Проблема:** Зелёные точки привязки (snap) отображались только в Selection tool, но не в Line tool.

**Исправление:** Добавить условие `|| currentTool === 'line'` в `render.js` и обработчик `mousemove` в `index.html`.

### 5.5 Убран дублирующий prompt() для Text tool
**Проблема:** При добавлении текста вызывался дублирующий `prompt()` из обработчика в `index.html`, перекрывающий логику `mouse-events.js`.

**Исправление:** Удалён дублирующий обработчик из `index.html`, оставлен единый в `js/mouse-events.js`.

### 5.6 Исправление сборки (HTML минификация)
**Проблема:** HTML-минификатор с `minifyJS: true` удалял переменные встроенных скриптов (например, `allowOverlapBeforeNesting`).

**Исправление:** В `build.js` установлено `minifyJS: false` — встроенный JS в HTML больше не минифицируется.

### 5.7 Критическое исправление: логика раскладки (allowOverlap)
**Проблема:** После исправления в 5.3 был внедрён баг: `allowOverlap` инвертировался после раскладки (`allowOverlap = !allowOverlapBeforeNesting`). При повторном запуске раскладки это приводило к `minGap = -100`, что ломало алгоритм — детали накладывались друг на друга.

**Исправление:** Убрана инверсия `allowOverlap`. Восстановлен сброс в `false` перед каждой раскладкой (как в оригинальном коде):
```javascript
// index.html
allowOverlap = false;
window.allowOverlap = false;
// Кнопка также сбрасывается в "ВЫКЛ"
```

**Результат:** Повторная раскладка работает корректно — детали размещаются без наложения.

### 5.9 Диагональная раскладка (Fusion 360 style)
**Проблема:** Ручное копирование деталей вдоль линии требовало много кликов.

**Решение:** Реализован режим паттерна как в Fusion 360:

1. **Активация:** нажать кнопку «📐 Диагональная раскладка: ВЫКЛ»
2. **Клик на деталь:** выделяется и начинается режим перетаскивания
3. **Тянуть мышку:** появляется пунктирная линия с индикатором
4. **Стрелки ↑/↓:** менять количество (2–100)
5. **Отпустить мышь:** создаётся паттерн

**Техническая реализация:**

```javascript
// mouse-events.js
window.diagonalPatternCount = 2;  // Инициализация при клике
window.addEventListener('keydown', (e) => {
    if (e.key === 'ArrowUp') {
        window.diagonalPatternCount = Math.min(100, window.diagonalPatternCount + 1);
        render();
    }
    if (e.key === 'ArrowDown') {
        window.diagonalPatternCount = Math.max(1, window.diagonalPatternCount - 1);
        render();
    }
});

// createDiagonalPattern()
for (let i = 1; i < count; i++) {
    const t = i / (count - 1);
    const copyX = startPoint.x + dx * t - sourceNested.width / 2;
    const copyY = startPoint.y + dy * t - sourceNested.height / 2;
    // Создаём копию...
}
```

**Визуализация (render.js):**
- Сплошной контур — исходная деталь
- Пунктирные контуры — превью копий
- Зелёная пунктирная линия — направление паттерна
- Метка: `📐 N шт. ↑↓` с подсказкой `↑↓ меняют кол-во`

**Исправления:**
- ❌ Было: `prompt()` для ввода количества (блокировало интерфейс)
- ✅ Стало: стрелки ↑↓ для изменения количества
- ❌ Было: `sourceNested.baseHeight` (неправильный размер)
- ✅ Стало: `sourceNested.height` (как в mo.js)

**Результат:** Быстрое создание регулярных раскладок (болты, заклёпки, отверстия) в одном направлении.

### 5.10 Undo/Redo для листа раскладки (Ctrl+Z/Ctrl+Y)

2. **keyboard-events.js** — поддержка русской раскладки:

3. **mouse-events.js** — сохранение при перетаскивании:
   - Добавлен `saveState()` при начале перетаскивания деталей

4. **nested-part-operations.js** — отражение деталей:

5. **sheet-management.js** — операции с листами:

### 5.12 G-code экспорт для лазерной резки
**Задача:** Добавить возможность экспорта раскладки в G-code для лазерных станков.

**Решение:**

1. **Кнопка «🔥 G-code»** в панели инструментов «Детали» (рядом с 📑, 💰, 📊)
2. **`js/gcode-export.js`** — модуль экспорта:
   - Собирает текущий лист из `window.allSheets[window.currentSheetIndex]`
   - Извлекает геометрию деталей из `parts` по `partId`
   - Применяет трансформацию (как в `svg-export.js`):
     - Нормализация от `part.bounds.minX/minY`
     - Поворот вокруг центра bbox (`baseWidth/2 × baseHeight/2`)
     - Вычисление `refPoint` (левая-нижняя точка повёрнутого bbox)
     - Смещение: `X = nested.x + (rotatedX - refPoint.x)`, `Y = nested.y + (rotatedY - refPoint.y)`
   - Сохраняет данные в `localStorage` → открывает `gcode-editor.html`

3. **`gcode-editor.html`** — редактор G-code:
   - **Превью листа** с красными контурами деталей (масштабируется по размеру панели)
   - **Сетка 100 мм** и подписи размеров
   - **Настройки лазера:**
     - Скорость резки (мм/мин)
     - Скорость перемещения (мм/мин)
     - Мощность лазера (%)
     - Частота импульсов (Hz)
     - Высота сопла (мм)
   - **Настройки резки:**
     - Lead-in/out (ввод/вывод)
     - Длина ввода (мм)
     - Оптимизация путей (nearest-neighbor)
     - Комментарии в G-code
   - **Ползунок скорости симуляции** (×0.1 — ×5.0)
   - **Симуляция резки:**
     - Красная линия с glow проходит по контурам
     - Белая точка-«лазер» с красным glow
     - Жёлтая точка на старте контура
     - Подсветка строк G-code в правой панели
     - Остановка по кнопке «⏹ Остановить»
   - **Генерация G-code:**
     - Стандартный заголовок (`G21`, `G90`, `G17`, `M3 S…`)
     - Обработка `G0`/`G1` для всех типов объектов (line, rect, circle, polygon)
     - Lead-in/out вектора
     - Подъём сопла между контурами (`G0 Z10`)
     - Завершение (`M30`)
   - **Скачивание `.nc` файла**

**Техническая реализация:**
```javascript
// gcode-export.js — трансформация координат
const angle = nested.angle || ((nested.rotation || 0) * 20 * (Math.PI / 180));

function rotate(x, y) {
    const dx = x - cx, dy = y - cy;
    return {
        x: cx + dx * Math.cos(angle) - dy * Math.sin(angle),
        y: cy + dx * Math.sin(angle) + dy * Math.cos(angle)
    };
}

// Итоговые координаты
const finalX = nested.x + (rotatedX - refPoint.x);
const finalY = nested.y + (rotatedY - refPoint.y);
```

**Результат:** Пользователь может экспортировать раскладку в G-code для лазерной резки с визуальной симуляцией процесса.

### 5.13 Inline dimension input для линии (Fusion 360 style)
**Задача:** Быстрый ввод точной длины и угла при рисовании линии без отвлечения на панель свойств.

**Решение:**

1. **Плавающее поле ввода** (`<input id="lineDimensionInput">`):
   - Появляется рядом с курсором при первом клике (начало линии)
   - Placeholder показывает текущую длину и угол: `150.5 мм | 45°`
   - Поддержка форматов: `100`, `100|45`, `100 45`, `100,45`

2. **Обработка Enter:**
   - Парсит длину и опциональный угол
   - Применяет ортогональность если включена
   - Фиксирует линию и сразу начинает новую от конечной точки (полилиния)
   - Поле остаётся активным для ввода следующего сегмента

3. **Обработка Escape:**
   - Отменяет текущую линию
   - Скрывает поле ввода

**Техническая реализация:**
```javascript
// mouse-events.js
lineDimensionInput.style.display = 'block';
lineDimensionInput.style.left = (e.clientX + 5) + 'px';
lineDimensionInput.style.top = (e.clientY + 5) + 'px';
lineDimensionInput.placeholder = `${lengthVal} мм | ${normalizedAngle}°`;
```

**Результат:** Рисование линий с точными размерами стало быстрее — не нужно переключаться на панель свойств.

### 5.14 Рефакторинг: панель свойств вынесена в отдельный модуль

- Кэшированию браузером

2. **Исправление порядка загрузки:**
   - `properties-panel.js` загружается **ДО** `mouse-events.js` (нужен `getInitialObjectPosition`)
   - `properties-panel.js` загружается **ДО** `tool-handlers.js` (нужен `getSelectionCenter`)

3. **Исправлены потерянные функции:**
   - `getInitialObjectPosition` / `restoreInitialObjectPosition` — для перетаскивания
   - `moveLineEndpoint` / `findConnectedLines` — для изменения длины с сохранением связей
